# react-native

Framework for building native iOS and Android apps with React — JavaScript drives real platform views, not a webview. Meta-born and now React Foundation-owned (the repo moved from facebook/ to the react org in early 2026), it remains the default JavaScript route to native mobile.

## Reception

- Native build and bundler toolchain friction dominates the most-reacted issues: Android build-variant resolution failures top the tracker ([react/react-native#35210](https://github.com/react/react-native/issues/35210), 912👍, since marked fixed and closed), alongside recurring Metro/packager module-resolution pain ([#4968](https://github.com/react/react-native/issues/4968), 584👍; [#21310](https://github.com/react/react-native/issues/21310), 598👍) — all now closed.
- The "Lean Core" umbrella effort ([#23313](https://github.com/react/react-native/issues/23313), 495👍, closed) reflects a sustained community push to slim the framework by extracting non-essential modules into standalone community packages.
- A non-technical naming dispute — a maintainer's existing open-source project name being taken — was the second-most-reacted issue on the tracker ([#30395](https://github.com/react/react-native/issues/30395), 873👍, closed), a signal of broad community attention rather than a technical limitation.
- Actively maintained on a fast cadence — 20 tracked releases at a ~7-day median interval, latest 2026-07-08 — against a very large open backlog (~1,022 open issues including PRs); the README names no adopters, so public production-user signal is limited.
